00 · Plan de ataque

El orden que ahorra más tiempo

La instalación de Zabbix, Grafana y n8n es lo único que tarda (descargas). Por eso se monta primero el borde de Internet y el servidor, y mientras el servidor instala, configuras el resto de routers.

  1. PNETLabImágenes, RAM y red de VMware. ≈ 10 min
  2. Topología y configuracionesCon el atajo automático ≈ 15 min; a mano, secciones 02–08 ≈ 90 min.
  3. R2, SW1, SW2Internet, VLAN, ACL, NAT y EtherChannel. ≈ 10 min
  4. SRV-MONIP, SSH y lanzar los scripts de instalación. Corren solos ≈ 20 min
  5. Servidores, R1 y EIGRPMientras instala: DNS, WEB, DHCP, R1, R3–R8. ≈ 20 min
  6. OSPF + MikroTikR9, R10, R11 y PCs. ≈ 15 min
  7. Zabbix, Grafana y TelegramAgregar equipos, crear el bot, alertas y flujo n8n. ≈ 25 min
  8. Pruebas y capturasChecklist de 23 evidencias. ≈ 40 min
Decisiones de diseño (para justificar en el informe)
  • R1-Pamplona es el router frontera RIP ↔ EIGRP y R3-Paipa el frontera EIGRP ↔ OSPF. Solo hay un punto de redistribución entre cada par de dominios, así no se forman bucles de rutas.
  • R2-Pamplona es el router de borde: ruta estática por defecto hacia Cloud0, NAT con sobrecarga (PAT) y la ruta por defecto se anuncia por RIP (default-information originate), llega a EIGRP por redistribución y R3 la inyecta en OSPF.
  • OSPF multiárea: área 0 = R3, R9, R10; área 1 = enlace R10–R11 y LAN Sogamoso. R10 es el ABR. El equipo multimarca (MikroTik CHR) va en R11, el extremo de la cadena, como recomendó el profesor: si falla, no tumba el resto.
  • EtherChannel LACP (Po1, 2 enlaces) entre Switch1 y Switch2, troncal 802.1Q.
  • Se agrega la VLAN 99 de gestión (192.168.99.0/24) para el servidor Zabbix/Grafana/n8n. El PDF trata Gestión como zona aparte, y así el monitoreo no choca con la regla “VLAN 10 nunca a VLAN 40”.
  • DNS1, Servidor web y DHCP son routers IOL livianos con ip dns server, ip http server y ip dhcp pool: consumen poca RAM y se configuran pegando un bloque.
01 · Preparación

Antes de abrir PNETLab

1. Red de VMware (evita el error más común)

Revisa la IP de tu máquina PNETLab.

Cloud0 entrega a R2 una IP de la misma red NAT de VMware donde vive PNETLab (ej. 192.168.80.x). Si el tercer octeto de esa red es 5, 6, 7, 10, 15, 16–25, 30, 40, 50 o 99, choca con el direccionamiento del proyecto. En ese caso: VMware → Edit → Virtual Network Editor → VMnet8 → cambia la subred a otra (ej. 192.168.80.0) y reinicia la VM.

2. Descargar las imágenes

Imágenes del proyecto con ishare2

SSH a PNETLab · root / pnet

Conéctate con MobaXterm: Session → SSH, host = IP de PNETLab, usuario root, clave pnet.

  1. Instala ishare2 (solo si al escribir ishare2 sale “command not found”).
    Instalar
    curl https://ishare2.sh/install | sh
  2. Busca las imágenes. Pega una línea a la vez y anota el número de la columna ID.
    Buscar
    ishare2 search bin
ishare2 search qemu mikrotik
ishare2 search qemu ubuntu
  3. Descarga las cuatro escribiendo el comando con el número que anotaste:
    ImagenQué elegir en la listaComando (ejemplo)
    IOL L3 · routers y servidoresnombre con L3, ej. i86bi_LinuxL3-AdvEnterpriseK9ishare2 pull bin 12
    IOL L2 · switchesnombre con L2, ej. i86bi_LinuxL2-AdvEnterpriseK9ishare2 pull bin 13
    MikroTik · R11la 7.x más nueva (ej. mikrotik-7.17)ishare2 pull qemu 45
    Ubuntu · SRV-MONUbuntu server 20.04, 22.04 o 24.04 (no desktop)ishare2 pull qemu 87
    Los números del ejemplo son inventados: cámbialos por los que te salieron.
  4. Arregla permisos cuando terminen las descargas.
    Permisos
    /opt/unetlab/wrappers/unl_wrapper -a fixpermissions
  • RAM: la VM de PNETLab necesita al menos 12 GB (ideal 16 GB) y 4 núcleos. Los IOL consumen poco; el Ubuntu necesita 4 GB.
  • Anota el usuario y contraseña de la imagen Ubuntu (ishare2 / la tienda de PNETLab los muestra; suelen ser root/root o ubuntu/ubuntu).

3. MobaXterm para copiar y pegar

  1. En el login de PNETLab elige consola nativa (Native console / telnet) si te aparece la opción. Al hacer clic en un nodo se abrirá telnet://IP_PNETLAB:PUERTO.
  2. Si el clic no abre MobaXterm, crea la sesión a mano: Session → Telnet, host = IP de PNETLab, puerto = el del nodo (lo ves en la URL telnet del nodo; en PNETLab suele ser 32768 + ID del nodo).
  3. Pegar en MobaXterm: clic derecho o Shift+Insert. Pega un bloque completo y espera a que termine antes de pasar al siguiente.
  4. Truco para verificar todo al final: MultiExec (botón en la barra de MobaXterm) escribe el mismo comando en todas las pestañas, por ejemplo write memory.
Al encender un IOL por primera vez

Si pregunta Would you like to enter the initial configuration dialog? [yes/no], escribe no y Enter antes de pegar. Todos los bloques empiezan con enable / configure terminal y terminan con write memory.

Paso 2 · Encender y cargar todas las configuraciones

consola de PNETLab (root) · ≈ 3 min

PNETLab no aplica solo las configuraciones guardadas en el lab: los equipos arrancan como Router. Este script las escribe por la consola de cada equipo, todos a la vez: configuración completa, llaves SSH y write memory.

  1. En PNETLab: More actions → Start all nodes y espera unos 2 minutos.
  2. En la misma sesión SSH de PNETLab (root) pega el bloque completo.
  3. Al final muestra una tabla con cada equipo y OK. Si alguno no estaba encendido o queda en REVISAR, enciéndelo y corre otra vez python3 /root/cargar-configs.py; volver a correrlo no daña nada.

#!/usr/bin/env python3
# Carga la configuracion de cada equipo del lab ProyectoFinal-Redes2 por su consola telnet.
import base64, glob, os, re, socket, subprocess, sys, threading, time
import xml.etree.ElementTree as ET

labs = glob.glob('/opt/unetlab/labs/**/ProyectoFinal-Redes2.unl', recursive=True)
if not labs:
    sys.exit('No encuentro ProyectoFinal-Redes2.unl dentro de /opt/unetlab/labs')
root = ET.parse(labs[0]).getroot()
LAB_ID = root.get('id') or ''
NODES = {n.get('id'): n.get('name') for n in root.iter('node')}
TYPES = {n.get('id'): n.get('type') for n in root.iter('node')}
CFGS = {c.get('id'): base64.b64decode(c.text or '').decode() for c in root.iter('config')}

def find_ports():
    out = subprocess.run(['ss', '-ltnp'], stdout=subprocess.PIPE, universal_newlines=True).stdout
    ports = {}
    for line in out.splitlines():
        m = re.search(r':(\d+)\s+\S+\s+users:\(\("[^"]+",pid=(\d+)', line)
        if not m:
            continue
        port, pid = int(m.group(1)), m.group(2)
        nid = None
        try:
            cwd = os.readlink('/proc/%s/cwd' % pid)
            base = os.path.basename(cwd.rstrip('/'))
            if base.isdigit() and (LAB_ID in cwd or '/unetlab/tmp/' in cwd):
                nid = base
        except OSError:
            pass
        if nid is None:
            try:
                args = [a.decode(errors='ignore') for a in open('/proc/%s/cmdline' % pid, 'rb').read().split(b'\0')]
                if '-D' in args:
                    nid = args[args.index('-D') + 1]
            except (OSError, IndexError):
                pass
        if nid in NODES and (nid not in ports or port < ports[nid]):
            ports[nid] = port
    return ports

def clean(b):
    out, i = bytearray(), 0
    while i < len(b):
        if b[i] == 255 and i + 1 < len(b):
            if b[i + 1] in (251, 252, 253, 254):
                i += 3
                continue
            if b[i + 1] == 250:
                j = b.find(bytes([255, 240]), i)
                i = j + 2 if j != -1 else len(b)
                continue
            i += 2
            continue
        out.append(b[i])
        i += 1
    return out.decode(errors='ignore')

class Con:
    def __init__(self, port):
        self.k = socket.create_connection(('127.0.0.1', port), timeout=5)
        self.k.settimeout(0.2)
        self.log = ''
    def read(self, wait):
        end, data = time.time() + wait, b''
        while time.time() < end:
            try:
                d = self.k.recv(65536)
                if not d:
                    break
                data += d
            except socket.timeout:
                pass
        t = clean(data)
        self.log += t
        return t
    def send(self, line, wait=0.15):
        self.k.sendall(line.encode() + b'\r')
        return self.read(wait)

def do_ios(c, name, cfg):
    t = c.send('', 2)
    for _ in range(6):
        low = t.lower()
        if 'initial configuration dialog' in low:
            t = c.send('no', 5); continue
        if 'terminate autoinstall' in low:
            t = c.send('yes', 3); continue
        if re.search(r'[>#]\s*$', t):
            break
        t = c.send('', 2)
    c.send('enable', 0.5)
    c.send('configure terminal', 0.5)
    for line in cfg.splitlines():
        if line.strip() != 'end':
            c.send(line, 0.12)
    c.send('end', 0.8)
    if name.startswith('R'):
        c.send('configure terminal', 0.5)
        t = c.send('crypto key generate rsa modulus 1024', 5)
        if 'replace' in t.lower():
            c.send('no', 2)
        c.send('ip ssh version 2', 0.5)
        c.send('end', 0.8)
    c.send('write memory', 5)
    return name in c.send('', 1.5)

def do_vpcs(c, name, cfg):
    c.send('', 1)
    for line in cfg.splitlines():
        c.send(line, 4 if 'dhcp' in line else 0.6)
    c.send('save', 1.5)
    return name in c.send('', 1)

results = {}
def worker(nid, port):
    name = NODES[nid]
    try:
        c = Con(port)
        fn = do_vpcs if TYPES[nid] == 'vpcs' else do_ios
        results[name] = 'OK' if fn(c, name, CFGS[nid]) else 'REVISAR (el prompt no muestra el nombre)'
        c.k.close()
    except Exception as e:
        results[name] = 'ERROR: %s' % e

ports = find_ports()
todo = [(nid, ports[nid]) for nid in CFGS if nid in ports]
missing = sorted(NODES[nid] for nid in CFGS if nid not in ports)
print('Lab: %s' % labs[0])
print('Equipos encendidos encontrados: %d de %d. Configurando (1-2 min)...' % (len(todo), len(CFGS)))
if not todo:
    print('\nNo encontre consolas. Enciende los nodos (Start all nodes) y vuelve a correrlo.')
    print('Si ya estan encendidos, mandale esta salida a Claude:')
    os.system("ss -ltnp | grep -Ei 'wrapper|vpcs|qemu|iol' | head -20")
    sys.exit(1)
threads = [threading.Thread(target=worker, args=x) for x in todo]
for th in threads:
    th.start()
for th in threads:
    th.join()
print('')
for name in sorted(results):
    print('  %-20s %s' % (name, results[name]))
if missing:
    print('\nNo encontre la consola de: ' + ', '.join(missing))
    print('Encienden esos nodos y vuelve a correr:  python3 /root/cargar-configs.py')
print('\nFaltan a mano: R11-SOGAMOSO (MikroTik, seccion 07) y la ruta estatica de R2 (seccion 04, bloque 2).')
EOF

Despliegue automatizado. Para reducir errores de digitación y el tiempo de montaje, la topología se definió como un archivo de laboratorio de PNETLab (.unl, formato XML) que contiene los 38 nodos, sus 40 enlaces y la configuración de arranque (startup-config) de cada router Cisco IOL, switch, servidor y VPCS. #!/usr/bin/env python3
import json, sys, urllib.request
URL = "http://127.0.0.1/zabbix/api_jsonrpc.php"
USER, PASS, GRUPO = "Admin", "zabbix", "Redes2"
HOSTS = [  # nombre, IP de monitoreo, tipo
    ("R1-PAMPLONA",        "192.168.15.1",  "cisco"),
    ("R2-PAMPLONA",        "192.168.99.1",  "cisco"),
    ("R3-PAIPA",           "172.16.3.1",    "cisco"),
    ("R4-BUCARAMANGA",     "172.16.4.1",    "cisco"),
    ("R5-BARRANCABERMEJA", "172.16.5.1",    "cisco"),
    ("R6-CUCUTA",          "172.16.6.1",    "cisco"),
    ("R7-BOGOTA",          "172.16.7.1",    "cisco"),
    ("R8-MEDELLIN",        "192.168.50.1",  "cisco"),
    ("R9-TUNJA",           "192.168.5.1",   "cisco"),
    ("R10-DUITAMA",        "192.168.6.1",   "cisco"),
    ("R11-SOGAMOSO",       "192.168.7.1",   "mikrotik"),
    ("SW1",                "192.168.40.2",  "cisco"),
    ("SW2",                "192.168.40.3",  "cisco"),
    ("WEB-SERVER",         "192.168.30.2",  "cisco"),
    ("DNS1",               "192.168.20.3",  "cisco"),
    ("DHCP-SRV",           "192.168.10.2",  "cisco"),
    ("PC-MEDELLIN",        "192.168.50.10", "icmp"),
    ("PC-11",              "192.168.7.13",  "icmp"),
    ("CISCOIP-1",          "192.168.15.10", "icmp"),
]

def api(method, params, tok=None):
    body = json.dumps({"jsonrpc": "2.0", "method": method, "params": params, "id": 1}).encode()
    req = urllib.request.Request(URL, body, {"Content-Type": "application/json-rpc"})
    if tok:
        req.add_header("Authorization", "Bearer " + tok)
    res = json.load(urllib.request.urlopen(req, timeout=30))
    if "error" in res:
        raise RuntimeError(method + ": " + str(res["error"].get("data", res["error"])))
    return res["result"]

tok = api("user.login", {"username": USER, "password": PASS})
g = api("hostgroup.get", {"output": ["groupid"], "filter": {"name": [GRUPO]}}, tok)
gid = g[0]["groupid"] if g else api("hostgroup.create", {"name": GRUPO}, tok)["groupids"][0]

def plantilla(nombre):
    t = api("template.get", {"output": ["templateid"], "filter": {"host": [nombre]}}, tok)
    if not t:
        sys.exit("ERROR: no existe la plantilla " + nombre)
    return t[0]["templateid"]

T = {"icmp": plantilla("ICMP Ping"), "cisco": plantilla("Cisco IOS by SNMP"),
     "gen": plantilla("Network Generic Device by SNMP")}
TPL = {"cisco": ["icmp", "cisco"], "mikrotik": ["icmp", "gen"], "icmp": ["icmp"]}

for nombre, ip, tipo in HOSTS:
    if api("host.get", {"output": ["hostid"], "filter": {"host": [nombre]}}, tok):
        print("= ya existe:", nombre)
        continue
    if tipo == "icmp":
        iface = {"type": 1, "main": 1, "useip": 1, "ip": ip, "dns": "", "port": "10050"}
    else:
        iface = {"type": 2, "main": 1, "useip": 1, "ip": ip, "dns": "", "port": "161",
                 "details": {"version": 2, "bulk": 1, "community": "{$SNMP_COMMUNITY}"}}
    api("host.create", {"host": nombre, "groups": [{"groupid": gid}], "interfaces": [iface],
                        "templates": [{"templateid": T[x]} for x in TPL[tipo]],
                        "macros": [{"macro": "{$SNMP_COMMUNITY}", "value": "redes2"}]}, tok)
    print("+ creado:", nombre, ip)

def chequeo(host, key, tipo, nombre, desc):
    h = api("host.get", {"output": ["hostid"], "selectInterfaces": ["interfaceid"],
                         "filter": {"host": [host]}}, tok)
    if not h:
        print("! no existe el host", host)
        return
    api("host.update", {"hostid": h[0]["hostid"], "status": 0}, tok)
    try:
        api("item.create", {"name": nombre, "key_": key, "hostid": h[0]["hostid"], "type": tipo,
                            "value_type": 3, "delay": "1m",
                            "interfaceid": h[0]["interfaces"][0]["interfaceid"]}, tok)
        api("trigger.create", {"description": desc, "priority": 4,
                               "expression": "last(/%s/%s)=0" % (host, key)}, tok)
        print("+ chequeo de servicio:", nombre)
    except RuntimeError as e:
        print("= chequeo ya existente:", nombre, "-", e)

#!/usr/bin/env python3
import json, urllib.request
URL = "http://127.0.0.1/zabbix/api_jsonrpc.php"
BOT, CHAT = "%%BOT%%", "%%CHAT%%"

def api(method, params, tok=None):
    body = json.dumps({"jsonrpc": "2.0", "method": method, "params": params, "id": 1}).encode()
    req = urllib.request.Request(URL, body, {"Content-Type": "application/json-rpc"})
    if tok:
        req.add_header("Authorization", "Bearer " + tok)
    res = json.load(urllib.request.urlopen(req, timeout=30))
    if "error" in res:
        raise RuntimeError(method + ": " + str(res["error"].get("data", res["error"])))
    return res["result"]

tok = api("user.login", {"username": "Admin", "password": "zabbix"})
mt = api("mediatype.get", {"output": "extend", "filter": {"name": ["Telegram"]}}, tok)[0]
params = [{"name": p["name"], "value": BOT if p["name"] == "api_token" else p["value"]}
          for p in mt["parameters"]]
api("mediatype.update", {"mediatypeid": mt["mediatypeid"], "status": 0, "parameters": params}, tok)
admin = api("user.get", {"output": ["userid"], "filter": {"username": ["Admin"]}}, tok)[0]
api("user.update", {"userid": admin["userid"], "medias": [{
    "mediatypeid": mt["mediatypeid"], "sendto": CHAT, "active": 0,
    "severity": 63, "period": "1-7,00:00-24:00"}]}, tok)
act = api("action.get", {"output": ["actionid"],
                         "filter": {"name": ["Report problems to Zabbix administrators"]}}, tok)
if act:
    api("action.update", {"actionid": act[0]["actionid"], "status": 0}, tok)
print("Listo: Telegram activado en Zabbix para el chat", CHAT)
EOF

16 · Sustentación

Preguntas probables y cómo responderlas

Lo que más suele preguntar un profesor de redes sobre este montaje. Las respuestas son cortas, para que las digas con tus palabras.

Redistribución

¿Por qué se redistribuye solo en R1 y en R3?

Porque cada par de dominios se une por un único router: R1 une RIP con EIGRP y R3 une EIGRP con OSPF. Con un solo punto de redistribución por frontera no hay rutas que vuelvan al dominio de origen, así se evitan bucles y rutas subóptimas.

Redistribución

¿Qué significa metric 10000 100 255 1 1500?

Es la métrica compuesta de EIGRP para las rutas externas: ancho de banda 10000 kbps, retardo 100 (decenas de µs), confiabilidad 255, carga 1 y MTU 1500. EIGRP no puede traducir el costo de OSPF ni los saltos de RIP, así que sin métrica las rutas redistribuidas no se anuncian.

Redistribución

¿Para qué sirve subnets en redistribute eigrp 100 subnets?

Hace que OSPF redistribuya también las subredes (por ejemplo las /30 y las /24 de 192.168.x.x), no solo las redes con su máscara de clase. En OSPF aparecen como rutas externas O E2.

Redistribución

¿Por qué metric 3 al redistribuir hacia RIP?

RIP mide en saltos y no entiende la métrica de EIGRP. Se asigna una métrica fija de 3 saltos: es menor a 15 (el límite de RIP) y deja margen para los saltos que se sumen dentro del dominio RIP.

Ruta por defecto

¿Cómo llega la ruta por defecto hasta Sogamoso?

R2 tiene la estática 0.0.0.0/0 hacia Internet y la anuncia por RIP con default-information originate. R1 la recibe como R* y al redistribuir RIP en EIGRP se convierte en D*EX. R3 la tiene en su tabla y con default-information originate la inyecta en OSPF como O*E2. Por eso la redistribución de la ruta por defecto es controlada: solo la origina el borde.

Teoría

Si una red se aprende por varios protocolos, ¿cuál gana?

La de menor distancia administrativa: conectada 0, estática 1, EIGRP interna 90, OSPF 110, RIP 120, EIGRP externa 170. Por eso R1 prefiere la ruta por defecto de RIP (120) antes que una EIGRP externa (170).

OSPF

¿Por qué OSPF multiárea y qué hace R10?

Las áreas limitan la inundación de LSA y hacen la base de datos más pequeña. R10 es el ABR: tiene interfaces en el área 0 (backbone) y en el área 1, y resume las rutas entre ellas con LSA tipo 3. Toda área debe tocar el área 0.

OSPF

¿Cómo se elige el router ID?

Primero el configurado a mano con router-id; si no hay, la loopback con la IP más alta; si no hay loopback, la interfaz activa con la IP más alta. En el proyecto se pusieron a mano (9.9.9.9, 10.10.10.10, 11.11.11.11) para que sean predecibles.

Multimarca

¿Por qué un Cisco y un MikroTik pueden ser vecinos OSPF?

OSPF es un estándar abierto (RFC 2328). Basta con que coincidan el área, la subred, los temporizadores hello/dead (10/40 s), el tipo de red y la MTU. Por la MTU se puso ip ospf mtu-ignore en R10.

OSPF / EIGRP

¿Para qué sirve passive-interface?

Hace que el router siga anunciando la red de esa interfaz pero sin enviar hellos ni actualizaciones hacia la LAN. Así nadie puede conectar un equipo en la LAN, formar vecindad e inyectar rutas falsas, y no se gasta ancho de banda.

EIGRP

¿Qué son el sucesor y el sucesor factible?

El sucesor es la mejor ruta (menor distancia factible) y va a la tabla de enrutamiento. El sucesor factible es una ruta de respaldo sin bucles, que cumple la condición de factibilidad (su distancia reportada es menor que la distancia factible del sucesor). DUAL la usa al instante si cae la principal. Se ven con show ip eigrp topology.

EIGRP

¿Qué debe coincidir para que dos routers sean vecinos EIGRP?

El número de sistema autónomo (100), los valores K de la métrica y que estén en la misma subred. Los hellos se envían a la multicast 224.0.0.10.

ACL

¿Cómo hace la ACL para separar IP pares e impares?

Con la wildcard: 192.168.40.1 0.0.0.254. El 0 en el último bit obliga a que ese bit sea 1 (impar) y los demás bits del último octeto quedan libres, así que coincide con .1, .3, .5, … .255. Las pares no coinciden y caen en el deny hacia el DNS.

ACL

¿Estándar o extendida, y dónde se aplican?

La estándar filtra solo por origen. Se usó en las líneas VTY (access-class 10 in) para que solo la VLAN 40 entre por SSH o Telnet. La extendida filtra por origen, destino, protocolo y puerto, y se aplicó de entrada en las subinterfaces de las VLAN 10 y 40, cerca del origen, para descartar el tráfico antes de que cruce la red.

ACL

¿Por qué termina con permit ip any any?

Porque toda ACL tiene un deny any implícito al final. Sin esa línea, la VLAN 40 perdería Internet, el acceso a los otros dominios y el SSH a los routers. Las reglas van de lo específico a lo general.

NAT

¿Qué tipo de NAT se usó?

PAT (NAT con sobrecarga): todas las redes internas salen con la única IP de e0/3 y se diferencian por puerto. Además hay NAT estática por puerto (port-forward) para publicar Zabbix, Grafana, n8n y SSH del servidor de monitoreo hacia la red externa. inside = interfaces internas, outside = e0/3.

EtherChannel

¿Por qué LACP y modo active?

LACP (802.3ad) es estándar, a diferencia de PAgP que es de Cisco. En active el switch negocia por su cuenta. Los puertos deben coincidir en velocidad, dúplex, modo troncal y VLAN permitidas. src-dst-ip reparte el tráfico entre los enlaces según origen y destino, y si cae uno el Po1 sigue arriba con el otro.

VLAN

¿Cómo se enruta entre VLAN y cómo llega el DHCP a otras VLAN?

Con router-on-a-stick: R2 tiene una subinterfaz por VLAN con encapsulation dot1Q y es el gateway de cada una. El DHCP está en la VLAN 10, así que en las demás subinterfaces ip helper-address 192.168.10.2 convierte el broadcast DHCP en unicast hacia el servidor (relay).

Monitoreo

¿Cómo monitorea Zabbix los equipos?

Por ICMP (plantilla ICMP Ping, chequeo simple con fping cada minuto) y por SNMP v2c con la comunidad redes2, limitada por ACL al servidor 192.168.99.10. Las plantillas traen los disparadores; “Unavailable by ICMP ping” es la alerta de caída, y Zabbix la envía a Telegram. Además se vigilan los servicios web (TCP 80) y DNS.

Automatización

¿Cómo funciona el bot?

Telegram envía cada mensaje a un webhook de n8n, que necesita una URL HTTPS pública; por eso se usa un túnel de Cloudflare. El flujo inicia sesión en la API de Zabbix, consulta el último valor de icmpping de cada equipo y los disparadores activos, revisa la salud de Grafana, arma la respuesta según el comando en un nodo de código y la responde en el chat.

Diseño

¿Por qué la VLAN 99 si el diagrama no la tenía?

El PDF trata Gestión como una zona aparte. Con el servidor en la VLAN 40, la regla “VLAN 10 nunca llega a VLAN 40” le impediría monitorear al DHCP. En una VLAN propia, el monitoreo no interfiere con las políticas de acceso.
